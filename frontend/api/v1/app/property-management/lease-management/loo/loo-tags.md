# LOO Tag Reference

Domain: `Property Management > Lease Management`

Every `{{tag}}` a template author can drag into clause text: what it is called, what
it means, and exactly where its value comes from.

This is the companion to [README.md](./README.md#the-tag-registry), which describes
the registry's *shape*; this file is its *contents*. The catalogue is also served
live at `GET lease-management/loo-tags`, and that endpoint — not this page — is what
a client should build against.

**62 tags across nine categories.**

## How to read the "Resolved from" column

Three mechanisms, and the difference matters whenever a printed value looks wrong:

| Mechanism | What it means |
|---|---|
| **Path** | A dot path read against four roots — `loo.`, `facility.`, `lease_application.`, `lease.`. `LooTag::pathFor()` picks `maps_to` or `lease_maps_to` by how the LOO was prepared. A path rooted at the source the LOO was *not* prepared from resolves to `null`, which is the right answer rather than an error. |
| **Computed** | Assembled by a method on `TagResolutionService`, because no single column holds it — a list, a total, or a label built from several fields. |
| **Not resolved** | The source has not been agreed. The tag still gets a `loo_tag_values` row with a `null` value, so it appears in the editor as a field a reviewer fills by hand. Deliberately not filled from the nearest plausible column. |

A `null` from a **path** or a **computed** tag means the source is genuinely empty —
an offer with no guarantors prints a blank. A `null` from a **not resolved** tag
means nobody has decided where the value comes from. Collapsing the two would make a
pending decision read as an empty field, which is the one mistake a LOO cannot
afford.

"Re-resolved whenever the granted spaces change" marks the tags
`TagResolutionService::refreshSpaceDerived()` recomputes after a space is granted,
withdrawn or re-priced. A hand correction to one of those **is** replaced by that
pass — the spaces it was typed against have moved.

**Format** is the tag's `default_format`. It seeds the editor's FORMAT picker and can
be overridden per request: `currency` prints in the property's reporting currency,
`list` prints prose rather than bullets, `yes_no` prints Yes/No, and anything else is
read as a PHP date format. See [README.md](./README.md#tag-resolution).

## A note on `is_computed`

The registry's `is_computed` column is a **presentation** hint for the editor, not a
statement about the resolver, and the two disagree on eight tags:

- six are flagged computed but resolve by **path** — `tenant_name`, `tenant_address`,
  `landlord_name`, `facility_type`, `start_date`, `legal_fee_recorder`;
- two are flagged computed but are **not resolved at all** — `rent_review` and
  `landlord_address`, whose sources have never been agreed.

The "Resolved from" column above is derived from `TagResolutionService` itself and is
the accurate account. Use the flag for styling, never for logic.
